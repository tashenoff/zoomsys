# Сиды прайсов Zoomsys

Источник данных — `server/pricing.json`. Фронтенд получает эти записи через существующий `/api/pricing` и `PricingProvider`; fallback — согласованный `src/data/pricing.json`.

Из корня проекта можно посмотреть состав обновления **без подключения к базе**:

```powershell
npm --prefix server run seed:updates-2026 -- --plan
npm --prefix server run seed -- --plan
```

План перечисляет кандидатов из файла. Он не утверждает, что все они будут добавлены: существующие записи сохраняются.

## Команды для выбранной базы

Перед записью проверьте, что `DATABASE_URL` указывает на нужную базу. В текущей задаче реальные сиды и миграции не запускались. Production требует отдельного разрешения.

```powershell
# Сначала схема (включая product_options, step_mode/step_unit, параметры рулона).
npm --prefix server run migrate

# Для существующей базы: все изменения текущей задачи.
npm --prefix server run seed:updates-2026

# Для новой базы: весь поддерживаемый прайс.
npm --prefix server run seed
```

Также доступны `seed:wide-format`, `seed:advertising-stands`, `seed:garment-embroidery`. Они используют тот же механизм и общий справочник дополнительных операций.

## Что попадёт в прайсы и калькуляторы

- Визитки: исправленные PDF-тарифы; бейджи: индивидуальный расчёт вместо 7 ₸.
- Roland: винил 1,2 м, существующие ставки, припуск, стоимость остатка и разрешённые операции.
- Холст Mimaki/Roland: те же записи натяжки и подрамника с прежними ID и тарифами; из привязок рекламных стендов они исключаются.
- Стенды: кармашки с вариантами формата и текущими ценами, кайма.
- Текстиль: действующие материалы и прошивка 750 ₸/пог.м до 500 пог.м, далее договорная цена. Нестандартный флаг использует эти записи, отдельный фиктивный тариф флага не создаётся.
- Сублимация: `product_options` с кружкой белой/перламутровой; существующий тариф нанесения и минимумы.
- Ведомственные таблички: адресное переименование существующих двух позиций.
- Phaeton не добавляется в новую базу; исторические записи и заказы не удаляются.

## Повторный запуск и сохранность

Сид выполняется в одной транзакции с advisory locks. Ошибка откатывает весь запуск. Имеющиеся записи ищутся по естественным ключам (название, раздел/цветность/вариант в зависимости от таблицы); их ID не заменяются. Отключённые позиции не включаются обратно.

Обычный повторный запуск не перезаписывает цены, опции, ограничения и привязки, отредактированные менеджером. Заполняются только отсутствующие метаданные: варианты товара, спецификация многостраничной продукции, ширина/параметры рулона. Отдельно применяются адресные миграции текущей задачи:

- `price-corrections-2026.json`: цена/ширина меняется только при точном совпадении с известным старым значением. Отличающиеся значения сохраняются и попадают в `priceCorrections.unchanged` (сюда также входят уже исправленные/отсутствующие записи).
- Переименование табличек выполняется до поиска новых записей, чтобы повторно использовать старые ID.
- Перенос холста меняет только привязки операций и материалов; тарифы и сохранённые заказы не затрагиваются.
- Ранее созданные дубли автоматически не удаляются: ссылки старых заказов сохраняются.

Сиды не записывают клиентов и заказы. Примеров клиентов в них нет.

## Проверки

```powershell
node --test tests/catalog-seeds.mjs tests/card-calculation-controls.mjs tests/catalog-changes.mjs tests/garment-printing.mjs tests/canvas-catalog.mjs tests/wide-format-finishing.mjs tests/remaining-items.mjs tests/multipage.mjs
npm run build
```

`catalog-seeds.mjs` проверяет фактический сид, повторный запуск, сохранение ID/изменённых цен, отключённые позиции, откат ошибки, адресные исправления и цепочку сид → настоящий обработчик API → настоящий преобразователь фронтенда. Граница базы имитируется в памяти; запуск на PostgreSQL — отдельная проверка в тестовой базе.
